## Core Idea — Conceptual Explanation

A prototype represents a possible experience before the product is built. It can be a sketch, a sequence of screens, or an interactive mockup. AI can help explore a structure or generate an initial composition, but it does not decide what a person needs or check whether they can use it. A prototype's value is in making a hypothesis visible and gathering feedback early.

Figma publishes documentation about AI tools in its design environment. The guide consulted describes beta features and access restrictions that depend on the account type and organization; check their current status in the official help documentation before following a tutorial. Do not activate a subscription just to complete this practice: if you do not have the feature, draw the screen manually. Names, access, and terms may change, and you do not need to upload sensitive material.

A good design instruction describes the user, task, essential content, hierarchy, and visual constraints. “Design a beautiful app” gives no review criteria. “A mobile screen for finding a library's hours; show today's hours, the weekly schedule, and a visible contact button” makes it possible to check whether the prototype meets the need. Add states: no results, error, loading, and confirmation. An attractive image does not guarantee that the flow works.

Also review accessibility and readability. Check that text is easy to read, buttons have clear labels, hierarchy does not depend on color alone, and controls are distinguishable. A prototype does not replace a test with users or a technical accessibility evaluation. Do not use real names, portraits, or data in examples, and check rights before reusing generated or third-party images.

## Concrete Example

You want to prototype a screen for booking a place at a fictional workshop. The main action is to choose a session and confirm. Before generating anything, define what must be visible: the workshop name, date, available places, selection button, and a confirmation message. If the prototype hides availability or gives two buttons equal prominence, the problem is hierarchy, even if the composition looks modern.

## Guided Practice — Step-by-Step

1. Write down a need in one sentence and define who has it. Use an invented case with no customer information.
2. List five required elements and two states that should appear if something fails or is unavailable.
3. In Figma, use an AI feature only if the current documentation and your account show that it is available. Describe the task and hierarchy, not just a style. If you do not have access, create the same wireframe with shapes and text.
4. Check whether every item on the list appears and whether the main action is clear without explanation. Mark each condition as met, missing, or needing a test.
5. Ask another person to explain the next step by looking at the prototype, without you giving hints. Record where they hesitate and change only what is necessary.

No code integration or specific generation tool is needed to validate the exercise. The prototype is a hypothesis, not a complete production specification.

## Validation and Troubleshooting

If the AI invents buttons, text, or states, compare them with the requirements and remove them or justify their presence. If the design looks attractive but no one understands the main action, change the hierarchy and labels before changing colors. Check size, contrast, and reading order with available tools or official guides; do not declare conformance based only on a quick visual inspection.

## Common Mistakes

- Treating a generated screen as a tested product or one ready to publish.
- Asking “make it beautiful” without prioritizing the task, content, or states.
- Uploading screenshots with personal data or brand elements without permission.
- Confusing access to an AI feature with authorization to use it in any project.
- Evaluating the prototype only on aesthetics rather than comprehension and accessibility.

## In Summary

AI can speed up visual exploration, but the problem and criteria are still yours. Specify content and states, create a fictional screen, and test whether the main action is clear. Use current features only if they are available, and review every element before moving on to code.
