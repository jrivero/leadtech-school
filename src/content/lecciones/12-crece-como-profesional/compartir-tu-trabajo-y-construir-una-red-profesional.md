## Comparte evidencia, no una promesa

Un portfolio no tiene que ser una colección grande ni una página sofisticada. Su función es ayudar a otra persona a entender qué construiste, qué decisiones tomaste y qué aprendiste. Puedes mostrar un repositorio, una demo sencilla o una reflexión con capturas y pasos de prueba. Si todavía no quieres publicar código, prepara esos materiales en una carpeta local y comparte solo aquello con lo que te sientas cómodo.

Elige un proyecto pequeño cuyo alcance puedas explicar. Por ejemplo, un organizador de tareas que guarda datos de muestra en el navegador. Si no tiene servidor, usuarios reales ni persistencia remota, dilo con claridad: es un prototipo local, no una aplicación lista para producción. Explicar un límite demuestra criterio; presentarlo como una función completa crea expectativas equivocadas.

## Haz que el proyecto se pueda entender

Añade un README o una nota equivalente con estos apartados:

- **Qué problema explora:** una o dos frases sobre la necesidad y las personas usuarias imaginadas.
- **Qué incluye:** funciones terminadas y, si procede, qué queda fuera.
- **Cómo probarlo:** requisitos, pasos de inicio y un recorrido corto que se pueda repetir.
- **Decisiones:** una elección técnica que hiciste y por qué, sin convertirla en una regla universal.
- **Comprobaciones:** pruebas ejecutadas y resultados observados. No digas “está probado” si solo abriste la pantalla.
- **Limitaciones y siguiente paso:** un error conocido, una duda o una mejora concreta.

Puedes retomar uno de los proyectos del bloque anterior y hacer visible el recorrido entre necesidad, implementación y comprobación. Si usaste asistencia de IA, distingue qué sugerencia recibiste, qué decisión tomaste y qué pruebas ejecutaste; no des por verificado el código solo porque se generó. En una demo de preguntas sobre documentos, por ejemplo, muestra de dónde procede un fragmento y qué ocurre cuando no hay evidencia suficiente. Así el portfolio enseña no solo una pantalla, sino también tu criterio de calidad y seguridad.

Incluye una imagen o una demo solo si ayuda a comprender el comportamiento. Comprueba que los enlaces funcionen y que el texto alternativo describa las imágenes importantes. Antes de compartir, busca claves, tokens, direcciones privadas, datos personales y archivos que no deban hacerse públicos. Usa información ficticia en capturas de ejemplo. Si trabajas con un repositorio alojado, revisa sus opciones de visibilidad; la documentación de GitHub explica cómo funciona el README del perfil, pero no necesitas activar un perfil público para completar esta práctica.

## Comparte para iniciar una conversación

Una invitación útil presenta el proyecto en pocas líneas: qué es, qué parte quieres enseñar y qué comentario te ayudaría. Por ejemplo: “He creado un prototipo de lista de tareas para practicar filtros. ¿Puedes probar los pasos del README y decirme si se entiende cómo marcar una tarea como terminada?”. Esa petición es más fácil de responder que “¿Qué te parece todo?”.

Construir una red profesional no es enviar el mismo mensaje a muchas personas. Empieza en espacios donde puedas participar de forma respetuosa: una comunidad técnica, una revisión entre compañeros, un encuentro local o un proyecto colaborativo. Lee las normas, aporta una pregunta concreta y ofrece comentarios útiles cuando tengas conocimiento. Si alguien te ayuda, agradece el tiempo y cuenta qué cambiaste después.

No presupongas que cada conversación se convertirá en una colaboración, recomendación o empleo. Compartir trabajo puede ayudarte a aprender, pero no garantiza una respuesta ni un resultado profesional. El valor inmediato está en practicar cómo explicar tu trabajo, escuchar una observación y decidir si la incorporas.

## Práctica verificable

Elige una de estas tres salidas: un repositorio con README, una demo acompañada de instrucciones o una reflexión escrita sobre un proyecto. Completa los apartados anteriores con datos reales de tu proceso. Añade una limitación que todavía exista y una captura o ejemplo reproducible si aporta claridad.

Por último, comparte la muestra con una persona de confianza o revísala en voz alta como si esa persona no conociera el proyecto. Anota una pregunta específica para recibir feedback y registra la respuesta o, si aún no la tienes, la pregunta que queda pendiente. La práctica está completa cuando existe una muestra comprensible y puedes explicar qué hiciste sin atribuirte trabajo ajeno ni ocultar lo que falta.
